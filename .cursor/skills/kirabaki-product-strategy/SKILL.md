# KIRABAKI Product Strategy

Do not blindly implement features. Ask: **does this strengthen KIRABAKI’s moat?**

## Moat (must compound)

1. Structured financial knowledge
2. Deterministic reasoning engine
3. Longitudinal financial memory / Twin
4. Decision → action → outcome history
5. Evaluation datasets
6. Malaysia tax / regulatory knowledge (when that phase is active)
7. UX people return to (Journey, Next Move, FIND)
8. Security / privacy for highly sensitive data

Commodities (do not chase): receipt OCR, bank connect, AI chatbot, “we have AI.”

## Gate question

Does this improve Financial Intelligence, Journey, Find, Plan, Action, Knowledge, or Retention?

If no → not a current priority. Say so and stop.

## Core loop

`KNOW → UNDERSTAND → FIND → PLAN → DECIDE → ACT → CHECK → IMPROVE`

North star: **Financial Improvement Rate** — users who complete a KIRABAKI-supported improvement per month. Not transaction count or chat volume.

First proof: can KIRABAKI make the founder make one better financial decision this month?

## Advance only on gates

See `docs/STATUS.md` for done / current / next. Phases live in `docs/ROADMAP.md`. Do not advance because you are bored.

## Year-1 / until-MVP bans

- Cryptocurrency, stock trading, robo-investment, lending, insurance marketplace, bank
- Social, marketplace, 100 integrations
- Native iOS/Android, Capacitor/TWA “just in case”
- Microservices, custom LLM, AI-agent-for-everything, 50 dashboards
- Primary “Ask AI” navigation
- Specific regulated investment advice

## Pricing

Tiers in `docs/ICP-AND-GTM.md` are **unvalidated**. Do not encode plans in code until Gate 5.

## Before adding a feature

1. Which gate / milestone is this for? (`docs/STATUS.md`, `docs/MILESTONE-1.md`)
2. Which moat layer does it strengthen?
3. Can it wait?
4. Does it shame the user or invent advice? If yes, reject.

Read `docs/THESIS.md` and `docs/VISION.md` for the full thesis.
